# 主题动效分析与实施计划

日期：2026-10-03。分析基线：v1.5.20 / `10acfa0`。

实施更新：用户已授权实施。下文保留原始设计依据；已落地范围、设置方法、状态证据与保守降级见[统一动效系统](theme-motion.md)。

本报告覆盖当前仓库的共享运行时、三端 renderer/CSS、主题格式与导入、菜单栏/托盘/脚本入口、同步工具及测试。它是源码分析和设计方案，尚未实现新增动效，也没有新增实机或性能测试。外部 `dreamskin-cc` 网站不在本仓库内；涉及 Studio 格式的工作需要后续另行协调。

建议先建立统一动效控制，再做日常操作反馈，随后接入真实任务状态，最后扩展角色差分和背景氛围。视觉方向延续超天酱的像素、粉青配色与直播窗口元素：操作时短促响应，执行时局部提示，完成时一次反馈，阅读时保持安静。

## 1. 当前已有能力与缺口

| 范围 | 已有实现 | 新工作的重点 |
| --- | --- | --- |
| 首页装饰 | 跑马灯、reaction、信号与 spark 循环；Windows/Linux 还定义眨眼、轨道、心电、唱片和均衡器 | 把现有装饰与交互/状态关联；不要把已有循环当新增功能 |
| 基础交互 | 侧栏、输入框、命令面板、导航标记等已有约 110–180ms 的 hover/focus 过渡 | 统一节奏，补按下、选中、首次出现和结束反馈 |
| 组件识别 | `data-angel-component` 覆盖 composer、message、activity、permission、edited-card、subagent、terminal 等 | 可以定位组件，但不能据此认定“正在思考/成功/失败” |
| 降低动态效果 | 已有 `prefers-reduced-motion`、窄窗/分栏裁减；Linux 另有 `performanceMode: low/full` | 建立三端一致的关闭、轻量、完整策略和暂停机制 |
| 自定义主题 | Safe CSS 开放 12 个公共部件、hover/focus-visible 和受限 transition | 首轮使用内置动效；复杂动画目前不能靠导入 CSS 实现 |
| 原生入口 | macOS 菜单栏、Windows 托盘、Linux 脚本 | 增加一致的动效偏好；区分“应用主题中”和“AI 任务执行中” |

关键源码依据：

- [共享扩展](../runtime/internet-angel-extension.js)：组件分类在 281–746 行，刷新/输入法保护/清理在 785–915 行；当前观察器只订阅 `data-ds-part` 属性和相关结构变化，不提供完整任务状态事件。
- [共享扩展样式](../runtime/internet-angel-extension.css)：现有交互过渡在 57、148、515、566 行；降低动态效果规则在 1485 行。
- [基础样式](../runtime/dream-skin.css)：首页循环动画在 2470、2636、2698、2709 行；[Windows 样式](../windows/assets/dream-skin.css) 的眨眼/轨道等定义集中在 5758–6226 行。
- Windows 样式 5491 行的注释记录了子代理持续 filter/阴影动画的 GPU 开销，并已设为 `animation: none`；[Linux 对应样式](../linux/assets/dream-skin.css) 5516 行仍启用同名持续动画。这是代码中记录的性能问题，本轮没有重新测量。
- [同步工具](../tools/sync-runtime-assets.mjs) 将扩展 JS/CSS 同步三端，但基础 CSS/renderer 仅由共享源生成 macOS 版本，Windows/Linux 仍有独立实现。不能只改 `runtime/dream-skin.css` 就声称三端完成。

## 2. 可添加动效的位置

优先级：A 为首轮推荐，B 依赖状态或生命周期补齐，C 为可选增强。成本是相对复杂度，包含实现与验证，不代表排期承诺。表中的时间/幅度是建议参数，尚未测量。

| 编号 | 位置与动效 | 触发与可复用入口 | 价值、边界与成本 | 顺序 |
| --- | --- | --- | --- | --- |
| 01 | 输入框聚焦：粉青边缘光由弱到强，退出后平滑恢复 | `composer`、`:focus-within`；已有 focus 样式可延伸 | 高频操作可感知；只动装饰层 opacity，保持光标/高度/输入法候选框稳定。低 | A |
| 02 | 按钮按下：像素边框压入、图标轻微回弹 | `composer-action`、`message-action`、sidebar controls 的 hover/focus/active | 改进已有 hover，而不是再叠一套循环；80–140ms。发送/复制成功必须等真实结果，不把点击当成功。低 | A |
| 03 | 侧栏和终端 Tab：选中标记短距离过渡、未选中项渐退 | `sidebar-row`、`terminal-tab`、`aria-selected`/`aria-current` | 让导航切换清楚；只动标记，不移动整行或滚动内容。低 | A |
| 04 | 命令面板/菜单：首次打开时边缘与背景淡入 | `composer-palette`、menu/listbox、已有 open 状态 | 120–180ms，聚焦与键盘操作立即可用；原生已有动画时避免重复，禁止接管定位。中 | A |
| 05 | 首页建议卡/项目卡：首次进入的短促亮边与错峰显现 | 现有 Home deck / native suggestions；项目页新增专用标记 | 总时长控制在约 250ms 内；历史/虚拟化重挂载不反复播放，不重用 first-child 布局假设。中 | A/B |
| 06 | 权限待确认：新提示出现时边框呼吸一至两次后静止 | `permission` 与可见、当前请求的语义证据 | 有实用价值；现有识别含中英文文本启发式，需排除历史权限卡和普通 alert；绝不代替用户确认。中 | A/B |
| 07 | 任务执行：输入区旁的小信号灯或短轨道进入忙碌状态 | 拟新增任务状态适配层 | 先支持可信 busy，确认原生证据后才细分 thinking/tool-running；不用节点存在或停顿时间猜测。高 | B |
| 08 | 输出中：消息旁独立的接收信号灯、角色轻点头 | `message-assistant` + 可信 streaming 状态 | 表达正在输出；不重放打字机、不改文本、不按每个 token 重启动画。高 | B |
| 09 | 完成/失败/取消：一次爱心或勾、柔和警示边、平静收束 | 同一轮任务的明确状态转换 | 300–500ms 的装饰反馈；停止按钮消失不等于成功，取消不播放庆祝。高 | B |
| 10 | 工具执行卡：卡头状态点切换、展开图标旋转 | `activity`、`activity-header`、`activity-detail`，展开可用原生状态 | 展开反馈可先做；运行/成功/失败要补语义。代码输出区保持稳定，不画虚假百分比。中/高 | A/B |
| 11 | 文件变更卡：新结果到达时文件图标与统计区域轻亮一次 | `edited-card-*`，以变更批次/稳定身份去重 | 帮助发现新改动；不逐行移动 diff、不改变增删语义色、不在滚动重挂载时重复提示。中 | B |
| 12 | 子代理列表：当前处理项单个状态点、结束后归于静态 | `subagent-row` + 新增可靠任务状态映射 | 不恢复每行持续 filter/阴影。现有 archive 根据 section 顺序/类名推断，不能代表完成结果。高 | B |
| 13 | 主题切换：新背景解码完成后双层交叉淡化 | 三端 injector/renderer 的主题修订与清理边界 | 180–300ms；旧背景保留到新资源就绪，失败恢复旧主题。大图超过解码/纹理内存预算则直接切换，及时释放旧资源。只过渡装饰层，不延迟事务提交或隐藏内容。高 | B |
| 14 | 角色差分：专注、等待确认、完成的小表情/姿态 | 复用现有 blink/orbit/HUD，接入 07–09 的状态 | 主题辨识度最高；首轮仅支持已知内置背景，新表情需素材；不能把固定眼部坐标套到任意用户照片。高 | B/C |
| 15 | 背景氛围：角落少量星点、低幅漂浮或可选视差 | 主题自有 HUD/背景层，首页且空间足够时 | 可选完整模式；限量、限视口、后台暂停。大图平移和混合层成本需实测，不默认启用。中/高 | C |
| 16 | 设置/工具页：选项选中边缘过渡、折叠箭头反馈 | `settings-*`、environment actions；Projects/PR/Customize 需专用部件标记 | 统一日常体验；保留原生 switch 的尺寸/位移，不对整页或滚动容器做进出场。中 | C |
| 17 | 菜单栏/托盘：应用主题期间短时 busy 图标，完成恢复静态 | macOS `snapshot.busy`/operation 状态；Windows 主题应用结果 | 只反馈皮肤工具自身操作。使用真实结果，无假进度；Linux 提供等价配置与文本反馈即可。中 | C |

首轮最值得交付的组合是 01、02、03、04，加上 06 的可靠新提示反馈与 10 的展开反馈。07–09、12、14 组合成下一轮“任务状态与角色差分”。

## 3. 统一动效策略

### 用户选项

建议提供“跟随系统 / 关闭 / 轻量 / 完整”。跟随系统默认映射到轻量；系统要求减少动态效果时，所有模式都关闭非必要位移和循环，状态改用静态图标与颜色表示。用户关闭优先于主题作者的偏好。

- 关闭：关闭主题新增动画；不把暂停整个皮肤作为替代入口。
- 轻量：保留短交互和一次性状态反馈，不持续播放背景/粒子/角色待机循环。
- 完整：允许有限的首页装饰与角色差分；任务页仍优先保证阅读。
- 配置先存到客户端独立偏好中，由三个 injector 校验并写入独立 payload 配置；不偷偷向当前严格的主题 ZIP schema 添加字段。
- macOS 在主题子菜单增加入口（[AppDelegate.swift](../macos/menubar-app/Sources/CodexDreamSkinMenuBar/AppDelegate.swift)，342 行）；Windows 托盘增加等价选项（[tray-dream-skin.ps1](../windows/scripts/tray-dream-skin.ps1)）；Linux 提供明确的配置/命令入口，并设计现有 `performanceMode` 的兼容映射。

### 运行与性能边界

- 复用共享扩展的标记、合并刷新和清理机制，不为每种效果添加一个全页面观察器。
- 仅观察已确认状态节点的必要属性。保留 compositionstart/end 保护，不在中文输入期间重算布局或移动输入框。
- 新控制器统一处理 `visibilitychange`、页面导航、可见性、热重注入、主题切换和恢复；当前主题源码尚未提供统一的后台/离屏动效暂停机制。
- 用 CSS transition/keyframes 或局部 WAAPI 表达效果；优先独立装饰层的 transform/opacity，不假定它们无 GPU 成本。`will-change` 只在需要时短暂开启。
- 建议初始预算：任务视图最多一个持续状态指示，首页最多三个低频装饰通道；超额按优先级停掉氛围效果。参数在云端性能基线后再调整。
- 不持续动画 filter、backdrop-filter、大片阴影、整屏渐变背景位置、列表高度或正文尺寸。避免出现每个 token 都触发测量/写样式的链路。
- 特效节点 `pointer-events: none`、装饰内容 `aria-hidden`；系统减少动态效果时仍保留可读的状态提示。
- 所有新效果默认样式可见，移除动画类后立即恢复；不能让 animationend 成为正文显示或交互可用的前提。

### 状态识别

建议先建立 `unknown / idle / busy / needs-attention / completed / failed / cancelled` 状态合同；thinking、streaming、tool-running 仅作为有原生证据时的 busy 子状态。无证据则回到 unknown 的静态外观，不伪装成正常完成。

每个效果必须定义：识别依据、作用范围、触发边界、去重身份、结束条件、超时撤销、缺失时降级。路由切换和恢复历史任务不应重放完成庆祝。已有 `subagent-row` 或 `activity` 标记只是结构分类，不能直接充当执行状态。

应优先使用原生显式语义属性/事件，并把支持版本及证据写入选择器合同。不要把英文/中文状态词、历史消息内容、输出停顿或固定计时器作为唯一判断。现有 LOVE/SIGNAL 等装饰数字也不代表真实任务进度。

## 4. 自定义主题格式的约束

- [Safe CSS policy](../runtime/safe-css-policy.json) 只允许登记部件及 hover/focus-visible；允许 `transition-duration` / `transition-property`，不允许任意 `animation`、`@keyframes`、`@media` 或 transform。
- [Safe CSS validator](../runtime/safe-css-validator.mjs) 257–269 行将单次 transition 限在 0–400ms、每组最多四项。已有 `--ds-theme-motion-level` 虽在白名单中，[macOS 共享 renderer](../runtime/renderer-inject.js) 386 行却固定设为 `standard`，目前不是完整动效配置协议。
- [主题包验证器](../runtime/theme-package-validator.mjs) 290 行的精确字段检查不接受 `motion` / `performanceMode` 等新官方字段。Windows/macOS loader 也会重建 theme 对象，新增原始 JSON 字段不会自动传到页面。
- 首轮动画放在受信的共享运行时，不放宽 CSS 导入限制。角色新增素材先使用应用内置资源；当前“唯一背景图”的 ZIP 合同不能直接容纳多张表情图或视频。
- 后续如果开放主题作者配置，采用白名单 effect ID 和有界参数；同步主题 schema、导入/写入/导出、指纹、各端读取器、旧主题兼容及外部 Studio。保留拒绝未知字段、额外负载和任意脚本的原则。

## 5. 分阶段实施计划

| 阶段 | 交付内容 | 主要代码入口 | 完成条件 |
| --- | --- | --- | --- |
| 0：统一基础 | 四档偏好、减少动态效果策略、页面隐藏/离屏暂停、清理合同；处理三端现有持续动画差异 | 拟新增共享 motion policy/controller；三端 injector；扩展 cleanup；同步/打包清单 | 三端配置行为一致；反复注入不累积监听器/动画；关闭模式即时生效；建立性能基线 |
| 1：交互动画 | 01–04，以及具备可靠触发的权限提示、展开箭头 | `runtime/internet-angel-extension.js/.css`，必要的平台装饰宿主 | 鼠标/键盘反馈一致；输入法、光标、焦点、菜单定位和滚动不受影响；先形成小而完整的交付 |
| 2：真实状态反馈 | 状态合同及 fixture；07–12；可靠性不足的具体状态先禁用 | 共享状态适配层；`tools/selectors.json`；组件分类与观察器 | 能区分未知、忙碌、待确认、成功、失败、取消；历史任务/虚拟列表不重复播放；流式输出不扩大扫描频率 |
| 3：主题特色 | 14 角色差分、13 背景切换；按需加入 15 氛围效果 | 共享动效控制与三端自有背景/HUD；内置素材；切换生命周期 | 已知背景定位正确；窄窗/分栏自动裁减；加载失败回退；性能预算内才能默认启用 |
| 4：配置与生态 | 原生操作反馈、效果细分开关、可选主题作者白名单协议 | 菜单栏/托盘/Linux 入口；主题校验/读写；另行协调 Studio | 配置持久化及迁移可靠；主题不能覆盖用户关闭/减弱设置；导入合同回归完整 |

依赖关系：阶段 0 → 阶段 1；阶段 0 + 可靠状态证据 → 阶段 2；阶段 2 → 角色任务差分。背景切换可在阶段 0 后独立推进，但必须先明确热重注入与清理的所有权。阶段 4 的主题包扩展不是首轮动效的前置条件。

每阶段建议独立 PR；仅在获得后续实施指令后开始开发。确认阶段性实现、云端验证和 CI 后，再按仓库既有规则决定版本交付。

## 6. 验收与回归计划

下面是未来实现的验收计划，不是本轮已完成的测试结果。

1. 策略测试：四档设置、系统减少动态效果、用户关闭、非法配置、旧配置迁移、隐藏/恢复和取消。
2. 生命周期测试：初始/延迟挂载、跨任务导航、历史记录恢复、虚拟化复用、热重注入、主题切换失败、恢复皮肤；动画与事件全部能撤销。
3. 状态测试：原生证据缺失、过期、冲突，以及成功/取消/错误边界；不把停止按钮消失或归档列表位置等同于成功。
4. 云端 Chromium 验证：三端完整样式分别加载；首页/任务/设置/工具页/弹窗；浅色/深色；窄窗、宽窗和分栏；输入法、连续输入、文本选择、滚动、diff、菜单键盘导航。
5. 性能验证：同一页面以关闭动效为基线，比较空闲、流式输出、多子代理、大 diff 和切换后台。检查 long task、布局/重绘、动画数量、扩展 classifyRuns、内存/监听器增长；先设定可复现基线，再确认预算。浏览器测量不等价于三端真实客户端 GPU 测量。
6. 兼容回归：保留近期白屏修复的约束。内容宿主不因动效被隐藏、缩放、裁切；不要给 main/thread/原生 sticky 宿主整体加 transform。扩展 [current-codex-surfaces.test.mjs](../tools/current-codex-surfaces.test.mjs) 及现有 renderer/extension 测试。
7. 三端交付：同步检查、三端 payload 检查、Node 回归、Windows PowerShell 5.1/7、macOS Swift/脚本与安装包 CI。后续实际运行验证继续遵守“仅云端”限制，并注明是否运行了官方客户端。

## 7. 暂不优先的效果

- 整屏故障闪烁、强烈色差和高频扫光：干扰读代码，也很难满足降低动态效果要求。
- 对每条流式文本再做打字机、逐字跳动：重复原生输出行为，容易破坏选区、滚动和性能。
- 所有消息、diff 行、子代理图标同时持续呼吸：视觉噪声与 GPU 成本都随内容增长。
- 根据角色装饰数值展示“推理进度百分比”：目前没有足够状态证据。
- 默认引入视频壁纸、WebGL/大型粒子引擎或任意上传动画包：对首轮目标收益有限，还会扩大素材、兼容和导入合同的改动面。
- 重写原生页面切换、拖动整个聊天区或隐藏再显示内容列：近期版本适配已说明这些结构变化的维护成本高。
